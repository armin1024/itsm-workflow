# 草稿提取泳道图｜技术评审版

评审基线：itsm-workflow 0.10.1；整理日期：2026-10-19。

## 方案概述

tec01负责工单数据准备、提取记录、用户交互、草稿管理、审核与版本保存；itsm-workflow负责筛选操作、参数化、调用内网LLM和生成可校验的流程定义。**tec01主动提交工单数据，提取服务主动回报进度，不采用轮询领取任务。**

本图描述两端协作方案：执行侧能力在本项目实现；tec01的持久化、页面、Hermes渠道及审核发布需要下游配套实现，不表示本仓库已经包含tec01功能。

## 泳道图

```mermaid
---
title: 经验草稿提取泳道图（技术评审）
---
sequenceDiagram
    autonumber
    actor U as 用户 / 审核人
    participant T as tec01（页面 / Hermes渠道 / 存储）
    participant E as itsm-workflow（提取服务）
    participant L as 内网LLM

    U->>T: 选择工单，申请提取经验
    T->>T: 获取工单数据<br/>建立提取记录
    T->>E: 主动提交工单数据与提取任务
    E->>E: 校验工单与请求<br/>检查重复提交
    alt 请求不合法
        E-->>T: 拒绝受理，说明原因
        T-->>U: 展示问题，请用户修正
    else 请求合法
        E-->>T: 已受理，后台开始提取
        T-->>U: 展示提取中
        E->>E: 过滤失败与非只读操作<br/>去重并参数化SQL
        E-->>T: 回报处理阶段及过滤情况
        T->>T: 保存进度
        T-->>U: 更新当前提取阶段
        alt 无有效SQL
            E-->>T: 返回无有效操作及过滤原因
            T->>T: 保存失败记录
            T-->>U: 请用户核对工单数据
        else 存在有效SQL
        E->>L: 提交任务背景与参数化候选步骤
        Note over T,L: 进入分析时回报一次；等待期间不发送定时心跳
        alt 模型分析与流程校验成功
            L-->>E: 返回中文摘要、步骤目的与参数语义
            E->>E: 组装流程草稿<br/>校验节点、连线与SQL
            E-->>T: 返回结构化草稿、校验结果及过滤说明
            T->>T: 保存待编辑草稿
            T-->>U: 展示可视化流程，供人工修正
            U->>T: 编辑参数、数据库路径及必要的人工/条件节点
            T->>E: 提交发布前流程校验
            E-->>T: 返回规范化定义与校验结论
            alt 校验通过，且人工审核通过
            T->>T: 保存不可变版本<br/>固定定义与内容哈希
                T-->>U: 发布完成，可用于后续匹配与执行
            else 校验或审核未通过
                T-->>U: 展示问题，返回编辑或退回草稿
            end
        else 分析或校验失败
            E-->>T: 返回提取失败与可读原因
            T->>T: 保存失败记录
            T-->>U: 展示原因，允许修正后重新提取
        end
        end
    end
    Note over T,E: tec01保存生产数据；提取服务只保留短期任务
```

## 评审要点

1. **程序控制可信边界。** 只从明确成功的安全SQL读操作形成候选，过滤失败、无效和重复操作；具体历史条件值改为参数，保留可核对的过滤说明。
2. **LLM辅助提炼，不负责执行。** 模型总结中文名称、摘要、用途及参数语义，程序组装并校验草稿；没有有效SQL或分析失败时，不生成可直接发布的经验。生产取证数据与模型输入仍需遵循内网数据权限和脱敏要求，不应假定所有自然语言都已完全匿名。
3. **自动草稿不是自动批准。** 当前自动提取以线性SQL读流程为主；条件分支、人工参数输入和跨节点结果绑定需要人工确认或补充，发布前重新校验。
4. **状态与内容在tec01。** tec01保存进度、失败、草稿、修改和发布版本；提取服务不建立第二套生产知识数据库。分析阶段不发送定时心跳，不能把“已受理”当作“已完成”，也不能把没有新进度直接判为失败。
5. **传输失败与提取失败分开。** 回报可重试且需幂等；回报未确认不能直接推断提取失败。进程缓存不是持久化保障，故障后由tec01核对任务再决定重投。
6. **发布后才进入使用链路。** 审核通过后，tec01固定规范化定义、版本与内容哈希；后续编辑不能悄悄修改已被计划引用的版本。

## 与独立调试的区别

Studio调试时，由浏览器本地存储代替tec01保存草稿。可直接粘贴工单数据，也可临时提供AOPS Key按工单ID取证；默认不向tec01同步。两种入口复用相同提取与校验逻辑。
