# 浏览器本地知识与执行调试手册

## 进入页面

启动服务后访问`http://<服务地址>:8089/`，输入`STUDIO_ADMIN_TOKEN`。页面提供执行中心、创建运行、知识与版本、知识抽取和内网API文档。

知识、提取结果、执行计划和节点结果存入当前浏览器的IndexedDB。后台不创建数据库，只在执行时保留内存上下文和用于页面读取的短期事件缓存。更换浏览器、域名或端口相当于打开另一份本地工作区；需要迁移时使用页面导出与导入。

## 知识抽取

1. 打开“知识抽取”。选择填写工单ID或直接粘贴JSON。
2. 通过工单ID取证时临时填写`AOPS_API_KEY`；直接JSON方式填写`info.data`对象和`audit_timeline.data`数组。
3. 默认只在本地抽取。需要同步时勾选同步tec01，并填写tec01已经创建的经验ID。
4. 提交后页面展示过滤SQL、参数化、分析工单、生成Workflow、校验Workflow五个阶段。分析阶段只在进入时回报一次，不发送定时心跳；等待期间没有新进度不等于失败。
5. 抽取完成后核对名称、中文摘要、步骤、参数、数据库和依赖，保存到浏览器本地知识库。保存的记录可再次编辑、导出或创建执行计划。

JSON输入的根节点约定：

```json
{
  "ticketInfo": {"id":100173,"event_title":"客户信息查询"},
  "auditTimeline": []
}
```

实际操作记录必须包含成功的`sql_exec_read`，否则提示没有有效操作。失败操作和重复SQL的过滤原因在提取诊断中显示。

## 手工添加和管理知识

进入“知识与版本”，点击“手工新建”。填写名称、摘要、匹配短语和系统信息，在画布中添加SQL读、条件、人工表单和结束节点，点击卡片编辑配置并连接步骤。页面沿用知识列表、执行中心、卡片画布和节点详情的统一布局。

“保存到浏览器”保存当前定义。列表支持多条知识；可以反复编辑、删除、导入和导出。修改知识后不会改变此前生成的执行计划，因为每条计划都保存了生成时的完整快照。

SQL参数既可来自运行输入，也可绑定前置结果。例如：

```json
{"kind":"NODE_OUTPUT","nodeId":"sql-1","jsonPointer":"/data/0/customer_id"}
```

根据SQL行数决定是否进入人工处理：

```json
{"path":"/nodes/sql-1/output/rowCount","op":"gt","value":0}
```

## 生成和保存计划

1. 打开一条知识，填写当前工单ID和页面按定义生成的运行参数。
2. 如需状态同步，勾选“将执行状态同步到tec01”，填写tec01已有的运行ID。
3. 在“创建运行”中点击“校验并保存测试计划”。这一步只生成并保存计划，不执行SQL。
4. 切换到“执行中心”，核对画布、数据库路径、SQL、参数来源及`#uatu-<工单ID>`注释。
5. 勾选已核对计划并点击“确认此执行计划”，无需填写`AOPS_API_KEY`，此时不执行SQL；确认时间保存在浏览器。
6. 临时填写`AOPS_API_KEY`，再点击“执行已确认计划”。按钮未满足条件时会显示具体原因，不再无说明地保持灰色。

执行时重新校验确认摘要与工单、Workflow和运行参数一致；内容变化须重新创建并确认。恢复前页面查询旧活动，仍在运行时不允许并发恢复。HTTP确认摘要不是生产权限机制，tec01负责正式用户审批。

浏览器支持同时保留多条计划，每条计划独立记录输入、执行节点、状态和结果。执行凭据只保留于页面输入状态及当前请求内存中，不进入IndexedDB、导出包或事件。

## 暂停、继续、取消和重试

执行时页面持续展示节点开始、完成、失败和人工等待事件。

- **暂停**：等待当前SQL节点到达安全边界，保存已完成结果并释放执行上下文。页面中的“暂停请求已提交”与“已暂停”有区别。
- **继续**：使用浏览器保存的节点状态、结果与分支信息重新下发，仅执行未完成节点。每次继续需重新提供`AOPS_API_KEY`。
- **取消并移除**：停止当前CLI进程并从浏览器计划清单移除该计划；知识本身继续保留。尚未运行或已经暂停的计划可以直接移除。
- **失败重试**：页面显示失败诊断；用户确认后从失败节点继续，已成功SQL不会重放。
- **服务重启或结果未知**：已提交结果保留。如果某条SQL执行结果不确定，页面要求先核对AOPS审计，再确认是否重新执行该节点。

刷新页面后，浏览器会重新读取本地计划并继续跟踪仍在后台执行的任务。服务器重新启动后不具备本地数据库恢复能力，恢复依据是浏览器保存的最近快照。

## 人工参数输入

到达`hitl_form`时，根据定义渲染一个或多个必填/可选字段，支持字符串、整数、数字、布尔值及范围限制。用户参考上游SQL结果后填写所需字段；也可以到达某一步时补充新参数。提交后校验字段，并把`values`绑定到后续节点。

例如：

```text
人工输入输出 /values/customer_id
```

等待人工输入时不占Executor执行槽位。用户回复后重新下发同一个计划快照继续。

## 是否同步tec01

默认关闭同步，此时本地抽取和执行不访问tec01。打开同步前，在服务端配置：

```dotenv
TEC01_BASE_URL=http://tec01:3421
TEC01_SERVICE_TOKEN=<回调令牌>
```

同步使用文档规定的统一回调接口，包含节点结果及人工交互。tec01需要预先创建对应经验或运行记录，页面不会替tec01建立生产数据。恢复计划沿用相同tec01运行ID，并生成新的`dispatchId`。

节点执行完但tec01未确认回调时，Executor停止进入下一节点，避免两端状态分叉。页面会保留已知结果并提示核实后恢复。

## 从一条SQL开始测试

1. 在“知识与版本”中点击“手工新建”，填写名称和用途。
2. 在画布保留一个SQL读节点和一个结束节点，连接为“SQL读→结束”。
3. 点击SQL卡片，填写数据库路径、只读SQL模板及所需参数。结束节点无需额外配置。
4. 保存到浏览器，在“创建运行”中选择该知识，输入当前工单ID与运行参数。
5. 核对并确认计划（无需Key），再临时填写`AOPS_API_KEY`执行已确认计划。
6. 到“执行中心”查看节点结果与真实失败诊断；需要更多操作时继续编辑知识并创建新计划。

最小Workflow定义示例，数据库路径需要改为当前环境真实路径：

```json
{
  "schemaVersion":2,
  "entryNodeId":"sql-test",
  "nodes":[
    {
      "id":"sql-test",
      "type":"sql_read",
      "title":"验证数据库只读访问",
      "config":{
        "databaseRef":"124/aops-t/aops-t/readonly/aops-t",
        "sqlTemplate":"SELECT 1 AS value"
      },
      "inputs":[],
      "approvalPolicy":"PLAN",
      "timeoutSeconds":600
    },
    {"id":"done","type":"end","title":"完成","config":{},"inputs":[],"approvalPolicy":"NONE"}
  ],
  "edges":[{"id":"next","source":"sql-test","target":"done","kind":"NORMAL"}]
}
```

表单与条件测试也通过同一流程完成。例如“SQL读→条件→人工表单→SQL读→结束”，没有结果的默认分支直接进入结束节点。

## 三方获取JSON约束

在API文档中查看`GET /internal/v1/runtime/schemas`，可获取Workflow、下发和抽取请求的JSON Schema，以及每种节点的配置、输入、输出约束。也可用`/internal/v1/runtime/schemas/{schemaName}`读取单份。

三方按Schema建立最小或完整Workflow，先调用校验接口，再调用`POST /internal/v1/executions/dispatch`真实执行。暂停、继续、取消和表单回复沿用完整Workflow协议，详见[REST API](api.md)。

## 本地数据备份

通过知识或计划的导出按钮下载JSON，再在同一页面导入。浏览器数据属于当前站点，清除站点数据会删除本地知识和计划。取消运行按产品语义移除本地计划；需要保留结果时先导出。
# 0.13.0 本地存储与性能补充

升级后IndexedDB自动迁移到v2，列表摘要与节点结果分开保存；迁移失败回滚，不要删除站点数据，请先使用只读导出。出现标签页升级阻塞时关闭旧版标签页后刷新。

结果默认每页100行，可选200行，完整输出仍可导出。有活动任务时可见页每2秒、隐藏页每5秒同步，无活动任务不周期扫描。临时缓存过期或服务重启仍可能无法恢复未保存结果，不会自动重放SQL。

浏览器结果软预算256MiB。写入失败会显示“已暂停自动同步”，不推进已保存游标；先手动导出/清理安全终态输出，再点击恢复同步。清理不自动删除知识、计划或运行摘要，也不清理暂停、待输入、未知及待重试流程。HITL上下文为兼容仍存于单运行详情并按需展示，不属于全库列表读取。

服务器参数与资源错误见[性能实现说明](performance-optimization.md)及[分档配置](machine-sizing.md)。
